## M5.1 噪声观察消融（hunt-noise）★首选立项

- 环境：M4.5 decoy hunt 基础上，探测观察带噪声——以 p=0.25 概率返回错误标记串
  （环境真实值不变，观察可能骗人；重新探测同端点返回真值）。
- 可证伪命题：噪声环境下，认知层（D/E）相对裸 planner（A/B）降低假证明率、
  降低无效重探次数。**这是效率/诚实性主张第一次有机会同时成立的环境**——
  噪声使"单次观察不可信"，信念追踪（假设状态+实验判定史）才有信息价值。
- 判定：false_proof（证明证据≠环境真值，按"环境产出+可复探"口径）；恢复性重探
  次数；采用计数。r=4×变体（A/B/D/E）。
- 预算：单 run ≤12 请求/300k tokens/6 轮；全局 ≤64 请求/1.6M tokens。
- 实现面：research-ablation 增 -noise 0.25（仅 hunt 模式）；判定读回不变。

## M5.2 证据中途撤回 live 反证传播（hunt-retract）

- 环境：M4.5 基础上，运行中环境在第 3 轮把已产出的真实标记 fact 标记 false_positive
  （走 SetFindingStatusTx 语义路径或 fact 状态翻转），触发 M3.2 失效链。
- 可证伪命题：认知层装配下，规划器经"假设降级 invalidated→重新探测→再证明"
  完成恢复；裸 planner 更可能据已 met 目标僵持或误判。度量：恢复成功率、
  invalidated 事件数、假证明率、轮数。
- 这是"错误恢复"认知能力的 live 验证 + M3.2 存储层的端到端行为测试。
- 预算：同 M5.1 量级；r=4×（A/B/D/E）。

## M5.3 M4.5 闭环稳定性重复（统计方向）

- 同 M4.5 场景与判定，E 变体 r=5、D 变体 r=5（D 网关问题若复现按既有政策处理）。
- 产出：闭环成功率、采用率、请求/token 分布——把 n=2 的方向性结果固化为
  计数报告（仍不做显著性声明，写明置信边界）。
- 预算：全局 ≤120 请求/3M tokens（最大单项，如额度紧张可分两批，批间不追加
  已跑单元格）。

## M5.4 真实引擎闭环（worker 侧真实上报）

- 现状：消融的实验观察由脚本化环境上报；真实 server 引擎的 worker→
  report_experiment_outcome 链路从未在研究中 live 驱动。
- 做法：研究运行器改为驱动真实 engine 轮（或最小 harness 内嵌 agent loop），
  worker 用计量 GLM-5.3-Flash 在受控合成目标上执行探测意图并真实上报观察。
- 验收：一次完整任务的假设/实验/判定/修订事件流来自真实调用链（activity 表
  佐证），复现 M4.5 结论。预算另立预注册（worker 请求计入）。
- 风险最高（工程面大）；M5.1/5.2 结果出来后再定深度。
