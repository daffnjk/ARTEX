# M2.2 — Authenticated bounded acceptance resolver and premise verifier

Predecessors: M2.1 (68d7bdd), M1a.1 (be0d4e65).

Cognitive role: the acceptance anchor moves from offline fixtures to
authoritative storage. The resolver is authenticated (host-written versions
only) and bounded (per task/goal lookup, no requester-selected criterion);
the first domain verifier proves PREMISES (a capture contains a specific
marker under a frozen context) — never whole vulnerabilities or goals, per
the M1a boundary "domain rules only prove experiment premises/control
validity".

## Deliverables

- schema: `harness_acceptance` — append-only versioned frozen specs:
  UNIQUE(task_id, goal_id, version), full AcceptanceSpec fields,
  is_current pointer maintained by a host API inside one transaction
  (demote old current + insert new). Old versions stay immutable history;
  versions are never reused (unique constraint).
- db/harness_acceptance.go:
  `SetAcceptance(spec)` host API — validates, atomic version bump (new
  version must differ from current), keeps history;
  `AcceptanceResolver()` satisfying harness.AcceptanceResolver — returns the
  CURRENT spec snapshot by (task, goal); missing → error (kernel maps to
  acceptance_unavailable, fail-closed).
- harness/premise.go (stdlib-only): `NewPremiseMarkerVerifier(marker string)`
  — marker is host-supplied at registration (never from model input): all
  observations contain the marker → valid/supported; none → valid/refuted;
  mixed → unknown/inconclusive (contradiction is not adjudicated).
- Tests (PG): version bump + reread (the kernel's acceptance_changed path),
  version reuse rejected, immutable history, missing goal fail-closed,
  full-stack confirm via PG observations + PG acceptance + marker verifier.

## Explicitly out of scope

- Wiring workers/planner to consult evaluation before completion (M1b.3b/M2.3).
- Verifiers beyond premise scope; vulnerability-class verifiers (later M2).
- Auto-seeding acceptance from goals (needs goal→criterion mapping policy —
  host decides at task setup; deferred until M2.3 integration).
