# ARTEX 证据驱动认知智能体：分阶段实施方案

状态：M0 基线登记 + M1a 证据验收内核/可选完成复核门；不是完整自主认知系统。

基线：`daffnjk/ARTEX@e6ec56999175509551a1e43a3ee3b053d0941bd9`（0.3.15）。
本分支没有同步其他 fork，也没有修改根 `go.mod`、数据库 schema、许可证或测试范围。

## 1. 目标与边界

在相同模型、工具和预算下，研究“结构化观察、条件化结论、独立验收和假设修订”能否减少错误确认、无效实验及重复工作。保留现有 Planner/Worker、资产图、探索图与 PostgreSQL；不叠加第二个全局规划器，不增加攻击执行能力。

用户提供的《控制论视角下的 Harness Engineering 架构设计》作为工程启发：先定义通信契约，区分程序验收/独立评估/人工裁决，隔离评价上下文，跨任务改进先提案再发布。这些安排不是稳定性或收敛性的数学证明。没有复制该文章原文。

只在本地隔离、明确授权的实验环境验证。模型不得修改授权边界、验收标准、工具权限或发布规则。当前开关仅是两个已知工具入口的渐进式约束，**不是全路径安全隔离**。

## 3. 目标架构

```text
目标 / 授权范围 / 冻结验收条件
             |
现有 Planner ← 条件化 Claim / Hypothesis / 证据快照
             |
派发门 → 意图队列 → 领取门 → 有界 Worker → 受支持执行适配器
                                           |
                                  Observation + 原始材料
                                           |
                       写回门 → 程序验收 / 必要时独立 Reviewer
                                           |
                         共同完成门 → 分级结论与停止原因
```

四道门是同一存储层的领域规则，不是四个新 Agent。程序检查能回答的问题不送给模型；独立 Reviewer 不继承主会话叙事，但保留完整相关证据、反证、目标和条件。模型之间一致不能代替程序证明。

## 4. 里程碑、接入位置与验收

### M0：固定基线并建立错误样本（本次登记基线，未测原系统成功率）

记录 commit、模型、工具、配置、场景版本与预算。历史轨迹缺失时记为未知，不虚构发生率。建立有效/无效会话、过期条件、缺失证据、工具超时与矛盾观察等本地样本。不要接入任意真实网络做基线测量。

验收：每个指标有分母，每个案例可回放，失败标签不由被测 Agent 单独决定。

### M1a：只读验收内核与工具级复核门（本次代码）

`harness/` 为零第三方依赖包；`cmd/harness-eval` 仅处理本地 JSON 夹具。
`agent/assembly.go` 在工具解析、DB 覆盖之后，panic guard 之前增加复核包装器。

验收：未知验收器、伪造/缺失/过期证据不能确认；模型参数不能取消复核；关闭模式保持原行为；禁用工具不能被重新添加。`EvaluationReport` JSON 本身不是审批令牌。

### M1b：可靠性与完成权限收敛（下一独立改动集）

- 审计 `agent/planner.go` 的内存 todo；把计划所属任务、稳定 step ID、计划版本、依据引用、预期产出引用及状态保存到 PostgreSQL。先备份，新增迁移；不直接序列化内存对象后宣称语义已持久化。
- 存储写入采用期望版本比较；模拟两个 Planner 实例、重启、缓存失效和迟到结果，拒绝过期覆盖。
- 审计 `agent/tools.go` 的关键节点/连边/状态写入，合并为业务事务并传播错误。外部操作不进入长数据库事务。
- `prove_goal`、`goal_met`、平台和人工入口逐条登记；共同完成操作必须检查可信评估记录及当前条件，而非仅检查工具是否可见。
- 启动恢复区分“未执行”“执行中”“外部效果未知”；未知效果先对账，不盲目重放。

验收：有真实 PostgreSQL 的重启/并发/事务故障测试；空白、部分写入、旧计划覆盖都不能误报成功。预算耗尽、阻塞、人工停止与目标达成分开记录。

### M2：可信 Observation 与首个领域验收器

在已支持的本地执行通道自动采集观察：身份引用、对象、时间、上下文版本、执行记录、完整性、原始材料摘要与哈希。秘密值放受控存储，认知状态只存引用。受支持通道以外的 Bash/MCP 不宣称已经完全受控。

实现 PostgreSQL Resolver：基于认证主体与任务进行读权限检查；执行记录和材料必须由采集端生成。当前版本先拒绝跨任务引用；未来复用必须显式校验授权与血缘，不能放开一个布尔开关绕过。

首个本地域规则优先检查“实验前提/对照是否有效”，不以响应码或模型置信分单独确认技术命题。验收器的 ID、版本、输入条件和输出语义固定；证据、报告和目标升级在同一业务操作中关联。

验收：有效观察/无效会话/证据不完整/过期上下文均有集成样本；重复提交幂等，失效证据不会继续证明目标，人工确认有独立权限与审计。

### M3：假设驱动探索与隔离评估

增加条件化 Claim、竞争假设、证据缺口与 ExperimentSpec；Planner 每轮只接收相关增量和稳定引用。独立 Reviewer 输出意见及补证建议，不能自行写入已确认状态。

先对候选实验使用可解释的进展/区分价值/成本启发式，并保留准备与复核预算。没有观测概率模型时不得把启发式称为精确 POMDP 或期望信息增益。只有在可控环境中估计并校准概率后，再增加概率策略对照。

验收：前提变化时撤回或暂缓相关结论；选择变化对应新证据；避免只因短期无新增就剪掉所有长期路线。

### M4：慢回路与对照评测

失败轨迹生成 `ChangeProposal`，包含问题证据、影响组件、收益假设、退化风险和回放报告。审阅/批准/发布在任务执行循环之外；不自动改权限、验收器或提示词保护层。

A=固定基线，B=A+可靠性修复，C=B+结构化证据/验收，D=C+假设驱动规划，E=可选概率策略。相同模型、工具、预算；准备、复核和规划成本全部计入。按应用和场景结构划分未见测试集，方法卡与测试答案隔离。

指标：结论准确性、无效实验识别率、恢复成本、有效产出/预算、条件化覆盖率、自主完成率、人工升级次数、越界提议/阻断/实际行为、停止原因。不能仅靠“全部交给人”获得低错误率后宣称成功。

## 5. 本次数据契约

`EvaluationRequest`：冻结请求 ID、task/goal/experiment、context version、命题、criterion ID/version、证据 ID 与 SHA-256。没有工具执行命令、完整对话、模型置信度或写权限字段。

`Observation`：可信 Resolver 返回采集记录和原始字节；同一 ContextVersion 下允许不同 SubjectRef/ObjectRef，以保留对照条件。版本匹配只检查传入快照一致性，**不会主动感知真实环境是否已经改变**；M2 必须从权威状态获取当前版本并实现失效规则。

`EvaluationReport`：

| 实验有效性 | 命题结论 | 处置 |
| --- | --- | --- |
| valid | supported | confirm（仅可信注册验收器可以给出） |
| valid | refuted | not_supported（仅当前命题，不表示环境安全） |
| valid / unknown | inconclusive | review |
| invalid | inconclusive | retry（建议，不自动重放） |

完整性通过不等于实验有效。若没有对应的注册验收器，保持 unknown / inconclusive / review。
`ChangeProposal` 只校验提案的最小材料，`requires_human_approval=true` 表示需要批准，**不表示已经批准**。目前无持久化或自动发布功能。

## 6. 本地验证

无需目标网络、数据库、API Key 或第三方模块，使用 Go 1.23+ 与 race detector 所需本地 C 工具链：

```sh
sh scripts/test-harness-offline.sh
```

脚本仅复制新内核/CLI 到临时 Go 1.23 module，执行测试、race 检查、vet、构建与夹具验证，然后删除临时目录。**不修改仓库 go.mod，不代表完整 ARTEX 的测试。**

具备基线要求的 Go 工具链和依赖时：

```sh
go test -race -count=1 ./harness ./cmd/harness-eval
go test -count=1 -run '^TestGoalCompletion' ./agent
go build -o harness-eval ./cmd/harness-eval
./harness-eval -input examples/harness/intact-unverified.json
```

最后一条应返回退出码 **2**，报告 `review` / `criterion_unimplemented`。这不是错误：夹具来自操作者，不能被当成独立观测；CLI 故意不注册领域验收器。

退出码：0=confirm（当前 CLI 无对应注册规则）；1=输入/输出错误；2=review；3=retry；4=not_supported（当前 CLI 无对应注册规则）。

## 7. 渐进开启与回滚

默认空值或 `ARTEX_GOAL_COMPLETION_MODE=legacy` 保持原有行为。
在既有本地部署的进程环境中显式设置：

```text
ARTEX_GOAL_COMPLETION_MODE=review
```

重启实例，使后续组装的 Agent 工具一致生效。若通过 Compose 启动，需要将变量加入对应服务的 `environment`；只写入 `.env` 不一定传给容器。

review 模式会阻断两个已知模型完成工具的原处理函数，返回 `goal_review_required`，保留其他工具。无效的非空模式同样阻断。这不是经过领域验收后自动放行的最终实现；本次没有新增人工批准按钮。

回滚：切换为 legacy 并重启，或回退本分支提交。本次没有数据库迁移。回滚到 legacy 恢复的是旧行为，不能描述为仍拥有复核保护。
