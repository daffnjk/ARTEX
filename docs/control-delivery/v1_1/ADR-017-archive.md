# ENG-17 additive archive compatibility

Archive v4 extends the existing manifest with control contract metadata, context, budget accounts/reservations, action/result identities, immutable observations/evaluations, acceptance history, claims/dependencies, withdrawals, hypotheses/experiments/reviews and plan references. Identity references and executable grant/lease fields are excluded. Versions 1..3 still load for legacy tasks; a controlled snapshot missing its control audit fails closed.

Controlled archival/deletion retains the original audit and graph under a hidden soft-deleted task. It never disables append-only triggers. Archival freezes authority through the existing close transaction before hiding the task. Late result commits serialize with deletion and reject deleted roots. Legacy compaction and restore remain unchanged. This intentionally does not promise hot-store space reclamation for control audit; retention/purge requires a separately reviewed policy.

Restore creates a fresh paused task and exploration with revoked authority, zero contract version, no profile, no queue and context `restored`. Its immutable history records source IDs and an explicit task/exploration reference map. Historical node/plan/evidence IDs remain source-namespaced inside this history; none is inserted as live formal proof or runnable work. Fresh approval and a fresh plan/acceptance are required. The existing cold package is retained for its traffic/files; it is not installed as a new execution workspace. An authenticated task-bound download is available at GET /api/tasks/{id}/control/restored-history. This history is not consumed by planners, acceptance resolvers or dispatchers.
