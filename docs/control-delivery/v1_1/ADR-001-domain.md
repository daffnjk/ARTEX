# ADR-001: pure control contracts, preserving existing identities

Status: implemented for ENG-01; review pending.

control uses only the Go standard library. Existing PostgreSQL task/exploration BIGINTs remain unchanged; explicit distinct Go types and namespace parsers prevent accidental interchange. Host code must resolve tasks.exploration_id; ActionProposal has no task owner/approval/provenance/grant fields. New execution/attempt IDs are distinct strings generated by the host, not model attribution. Their persisted UUID protocol is implemented with the execution storage ticket, not guessed in this types-only change.

TaskContext has separate contract version, control epoch, context and criterion versions; task plan RowID/Revision remain in the existing store. No graph-wide version invalidates unrelated evidence. Direct/goal/coverage exclude legacy; migration adds the controlled fields in ENG-02 without upgrading historical tasks.

Strict proposal JSON uses the supplied v1 field allowlist, rejects unknown nested fields/trailing JSON, caps input at 16 KiB and limits references. Target matching is still ENG-03; shape validation is not authorization. Run/effect/cleanup stay separate; unknown is never translated to success. The legacy status mapping has one pure function for later completion integration.

Dependencies: control -> stdlib; execution -> control + interfaces; db -> control/port implementations; server -> composition. Existing harness stays the versioned evaluator. No new DB/backend, dependency upgrades or planner rewrite.

Runner now accepts an optional ticket or all, retaining the old ENG-00 invocation and fixed regression inventory. It hashes code/fixtures separately from changing progress/report documents; each run also binds the unchanged acceptance and log-validator files. Original packet manifest remains unedited. Original source/code-check.md trailing whitespace is retained because it is a hash-bound uploaded static reference, not new code.
