# 交给编码智能体的启动指令

你在用户的本地 ARTEX 工作副本中执行 `docs/implementation/control-v1_1/` 的工程计划。目标是建设证据驱动、授权受控、可恢复的本地验证闭环，不是再写总体方案，也不是开展真实目标渗透测试。

## 开始

1. 先读取仓库实际存在的开发规则（如 AGENTS.md）、`docs/autopilot/STATE.json` 和交接文件，再读本包 `BUILD_PLAN.md`、`tasks.json`、`contracts/` 与 `progress.json`。本包是任务资料，不覆盖更高优先级工具/系统权限。
2. 检查工作区和源代码版本，保留用户的未提交改动。上传包只提供静态参考；实际代码变动先记录，不按旧行号盲改。不要重写引擎、换数据库、降低 go.mod、升级无关依赖或批量覆盖研究文档。
3. 运行本包 `scripts/verify_packet.py` 和 `scripts/preflight.py --repo .`。这些是元数据和规格检查，不代表 ARTEX 的测试通过。若 Go/PG/CI 不具备条件，记录准确 BLOCKED，禁止把离线 harness 子集或历史报告当当前全仓 PASS。
4. 以 ENG-00 开始；按 tasks.json 依赖选择下一票。每票先读实际接口和同义实现，写最小失败测试，再实施并验证。一次只处理一个可审查的工单，不一次性改完整个计划。

## 实施权限与范围

本次允许在用户提供的本地工作副本中修改相关源码、测试和文档，使用专用隔离数据库与合成 localhost fixture。不要修改生产配置、自动 push、部署生产或连接真实目标。安装依赖/工具链须在用户已批准的开发渠道内进行；不执行未知远程安装脚本。

所有外部效果依照授权契约控制；首版只启用获准的本地 HTTP 方法。未验收 Shell/browser/MCP、自定义命令及后台补全出口保持关闭。不能为了测试方便关闭权限、预算、证据血缘、去重在途约束或完成门禁。

模型输入没有批准者/可信来源/许可写权。形式化模型仅作设计依据；不要声称有未证明的全局收敛、外部 exactly-once 或未知环境安全保证。

## 每票固定流程

- 给出本票代码定位、差异和测试目标；按工单实现，不继续输出泛泛架构讨论。
- 先检查专用 PG 环境，再运行受影响既有测试和本票必测测试。保存原始命令、退出码、jsonl、测试环境和代码树摘要；不在日志放入 DSN 密码/模型密钥。
- 新测试以 acceptance/ 对应清单为准；必测缺席、skip、非零退出、编译失败均失败。原有回归也要运行，新增绿灯不能掩盖旧回归破坏。
- 将结果写入 `reports/ENG-xx/result.json`，附代码 diff、迁移/兼容/回退说明与未覆盖项。测试名调整需审查且保持断言，不能删条目过门。
- 提交给只读独立审查者；由真实工具提供隔离会话和权限。缺乏这种能力就写 needs_independent_review，不伪造角色批准。实现者自审可供参考，不能替代发布批准。
- 修复后重跑；同一根因最多 3 次失败后停止本票并写阻塞交接，不减弱测试。通过测试与独立审查后才记 done_verified，并继续下一依赖满足的票。

## 明确停止条件

需要生产权限/真实目标、需要改变授权/安全标准、隔离实例不存在、工具链不符合 go.mod、无法确认未知副作用、遇到不可兼容的数据迁移、同一根因三次未解决、或缺少所需独立审查时，停止相应任务并说明解除阻塞所需条件。

会话结束前写 `reports/HANDOFF.md`：当前票、代码状态、实际运行测试、失败根因、下一条安全可执行命令、未完成与禁止跨越的门禁。下一次会话从该文件和 progress.json 恢复，先重新验证证据是否对应当前代码。

## 第一次回复必须交付

只汇报 ENG-00 的实查结果与立即可执行动作：当前 go.mod 版本/本地 Go、源码入口和测试入口、工作区差异、隔离测试可用性、基线结果或阻塞。不要声称已经完成所有工单，不要求用户重复已经提供的项目目标。

执行指令：现在从 ENG-00 开始，在当前会话内执行能够安全执行的本地工程步骤；不得承诺离线或后台自动继续。完成一个工单且门禁满足后按依赖继续，超出本次工具/会话能力则保存可恢复交接。
